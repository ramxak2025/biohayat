# ХАЯТ — мобильное приложение (iOS)

Нативное приложение магазина БАД «ХАЯТ» на Expo SDK 57. Каталог и данные
покупателя работают через общий с сайтом REST API
`https://new.biohayat.ru/api/v2`: сайт и приложение используют одну базу
товаров, покупателей и заказов. Подключение API v2 подготовлено к развёртыванию на VDS; до развёртывания
новые маршруты недоступны. У приложения нет отдельной базы. Старый
`/api/v1` сохранён для существующих веб-клиентов и не обеспечивает полный
контракт приложения.

## Запуск разработки

```bash
cd mobile
npm install
EXPO_PUBLIC_API_URL=http://localhost:3187/api/v2 npx expo run:ios
# нативная сборка + Metro; нужен Xcode 26.6 и локальный API из серверного worktree
```

Для локальной проверки используйте серверный worktree с API v2 и отдельной
тестовой базой. Локальные фикстуры не являются данными production:

```bash
cd /Users/ramazan/.codex/worktrees/hayat-shared-backend/Hayat
pnpm dev --port 3187
```

Для iOS-симулятора задайте `EXPO_PUBLIC_API_URL=http://localhost:3187/api/v2`.
Для физического устройства вручную замените `localhost` на LAN-адрес Mac:
`http://<LAN-IP>:3187/api/v2`. Устройство и Mac должны быть в одной сети.
Адрес также можно задать в `mobile/.env.local` либо передать при запуске Metro:

```bash
EXPO_PUBLIC_API_URL=http://localhost:3187/api/v2 npx expo start --dev-client
```

В релизной сборке используется `https://new.biohayat.ru/api/v2`. Значение
`EXPO_PUBLIC_API_URL` встраивается в приложение: после его смены перезапустите
Metro или пересоберите приложение. Не помещайте секреты в `EXPO_PUBLIC_*`.

## Архитектурные решения

### Почему не GSAP
Клиент просил «анимации как в GSAP». GSAP — браузерная библиотека: в React Native
она умеет только твинить свойства JS-объектов, то есть анимация шла бы по
JS-потоку и спотыкалась при загрузке данных, а `ScrollTrigger` без DOM просто
не запускается. Поэтому взяты **кривые** GSAP, а крутит их Reanimated на
UI-потоке (120 Гц на ProMotion). Соответствие проверено численно:

| GSAP | `Ease` в `src/theme/motion.ts` | максимальная ошибка |
|---|---|---|
| `power2.out` | `Easing.out(Easing.cubic)` | 1.1e-16 |
| `power3.out` | `Easing.out(Easing.poly(4))` | 0 |
| `back.out(1.7)` | `Easing.out(Easing.back(1.7))` | 2.2e-16 |
| `expo.out` | `Easing.out(Easing.exp)` | 0.008 |

### Нативный таб-бар
`expo-router/unstable-native-tabs` рендерит настоящий `UITabBarController`,
поэтому Liquid Glass, размытие, сворачивание при скролле и хаптика достаются от
системы, а не рисуются вручную. Цена решения — центральную «приподнятую» кнопку
каталога с сайта повторить нельзя (UITabBar такого не умеет), поэтому каталог
стал обычной вкладкой, а избранное уехало в кабинет.

### Стекло только на хроме
`GlassSurface` (см. `src/components/ui/glass-surface.tsx`) деградирует в три
ступени: iOS 26 Liquid Glass → `expo-blur` → сплошная подложка при включённом
«Уменьшении прозрачности». По HIG стекло не ставится под контент — только под
плавающие панели.

### Шрифт
Системный SF Pro вместо веб-Manrope: даёт Dynamic Type, правильную кириллицу и
то самое «эппловское» ощущение. Manrope остаётся фирменным шрифтом сайта.

### Данные
- Каталог запрашивается у общего API; публичные данные могут кэшироваться на
  устройстве. Данные покупателя и другие приватные ответы API никогда не
  записываются в персистентный кэш.
- Сессия хранится **только** в `expo-secure-store` (Keychain) и относится к
  конкретному API-бэкенду. После обновления со старой версии приложения войдите
  ещё раз, чтобы создать сессию для API v2. Старые локальные корзина и гостевое
  избранное из прежнего пространства хранения автоматически не переносятся;
  серверные заказы и избранное аккаунта сохраняются.
- Корзина хранится только на этом устройстве и не синхронизируется с сайтом или
  другими устройствами. При оформлении сервер проверяет весь состав корзины и
  применяет текущие цены из общей базы.
- Гостевое избранное хранит ID на устройстве. После входа оно добавляется к
  избранному аккаунта; карточки загружаются по ID через API, а не только из
  временного кэша каталога.
- `src/api/legacy.ts` содержит адаптер старых форматов. Полный функционал требует
  API v2.
- В мобильном приложении пока нет нативного интерфейса адресной книги,
  промокодов, реферальной программы и B2B/оптовых заказов. Наличие этих функций
  на сайте не означает, что они доступны в приложении.

### Трекер приёма
Отметки берутся из `GET /intake/{planId}/logs` с **локальной** датой устройства.
Данные из `plan.logs` использовать нельзя: сервер считает «сегодня» по UTC, и с
полуночи до 3 ночи по Москве пользователь видел бы вчерашний день.
`POST .../logs` — переключатель, не идемпотентен: при обрыве связи логи
перечитываются, повторный POST снял бы отметку.

### Текущая проверка интеграции

```bash
node --test tests/*.test.mjs
npx --no-install tsc --noEmit --incremental false
npx expo export --platform ios
npx expo export --platform android
```

На 2026-10-05 прошли 27 Node.js тестов, TypeScript-проверка и финальный
экспорт JS/Hermes для iOS и Android. В отдельном iOS-симуляторе проверены
общий каталог, вход, избранное в обе стороны, оформление, подтверждение и
детали заказа, видимого на сайте. На production-сборке локального сервера
прошли 13 групп HTTP/DB-проверок. Независимое ревью завершено без нерешённых
существенных замечаний. Подробности и границы проверки —
`docs/api-v2-verification.md` в серверном worktree. Подписанные IPA/APK не
собирались; публикация и развёртывание в production ожидают отдельного
явного одобрения.

## Иконка
`scripts/make-icons.mjs` собирает все варианты из брендовой марки: из PNG берётся
только альфа-маска. Светлый набор использует Чернила `#0F1D16` и Туман `#EEF1EA`,
а тёмный — Шалфей `#B3C3A6` на системной подложке.

Плагин `plugins/with-opaque-icon.js` снимает альфа-канал со светлой иконки внутри
prebuild: `@expo/image-utils` добавляет альфу всегда, а App Store за это
отклоняет сборку (`ITMS-90717`). Тёмный вариант не трогается — там прозрачность
обязательна по требованию Apple.

## Сборка и публикация

```bash
export EXPO_TOKEN=<токен expo.dev>
npx eas-cli@24.7.0 build   --platform ios --profile production
npx eas-cli@24.7.0 submit  --platform ios --latest
```

Ключ App Store Connect лежит в `credentials/` и **не коммитится**
(`.gitignore` + `.easignore`). Первый `submit` требует существующей карточки
приложения в App Store Connect: создать её через API нельзя — Apple запрещает
операцию `CREATE` на ресурсе `apps`.

## Структура

```
src/
  api/        клиент, типы контракта, эндпоинты, ключи кэша, адаптер старого API
  app/        маршруты expo-router (тонкие файлы, тело экрана — в src/screens)
  components/ дизайн-кит (ui/) и карточка товара
  screens/    экраны
  store/      сессия (Keychain), корзина, гостевое избранное
  theme/      токены дизайна и система движения
  lib/        форматирование, клиент запросов, уведомления
```
